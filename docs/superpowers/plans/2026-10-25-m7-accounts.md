# M7 Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Only signed-in, allowed users reach the launcher: Google sign-in through the system
browser, an API that issues its own tokens and computes the entitlement, a launcher gate with a
14-day offline grace, an Account app with devices, and an admin console v0 (users, settings,
audit log).

**Architecture:**
- `apps/api` (new, ADR-007): Fastify 5 + `fastify-type-provider-zod` + Drizzle over SQLite
  (`better-sqlite3`), run by Node 24 directly from TypeScript (type stripping, so the API's own
  code uses erasable syntax only). Modules `auth` (identity providers, tokens, launcher
  routes, admin web session), `users`, `entitlements`, `admin`, `settings`. Billing is off
  (FR-SUB-5, D21): every allowed user is on the seeded **Default** plan.
- `apps/launcher`: `main/auth/` (PKCE, loopback listener, `ApiClient`, `AuthService`), auth
  IPC + `auth.changed`, renderer `features/auth/` (gate screens, banner, offline badge) and
  `features/account/` (Account app). The renderer never talks to the API; main does.
- `apps/admin` (new, ADR-008): Vite + React SPA (TanStack Query, i18next, Tailwind) with
  `packages/ui` primitives; served by the API as static files (same origin), Vite proxy in dev.
- **Five PRs**, same loop as M6 (inline TDD with the ledger → lint, typecheck, test, test:e2e →
  fresh Opus reviewer for the branch → fix Critical/Important failing-first → PR → CI green →
  owner OK → squash-merge → main push run):
  **M7-0** M6 minors (Task 0, `fix/m6-minors`);
  **M7a** API foundation + launcher auth routes (Tasks 1–6, `feat/m7a-api-auth`);
  **M7b** launcher sign-in gate, offline grace, Account app (Tasks 7–11, `feat/m7b-launcher-auth`);
  **M7c** admin console v0 (Tasks 12–15, `feat/m7c-admin-console`);
  **M7d** docs, real-Google check, release v0.7.0 (Task 16, `chore/m7d-release`).

**Tech Stack:** New API deps: `fastify@5`, `fastify-type-provider-zod` (the major that supports
zod 4), `@fastify/cookie`, `@fastify/helmet`, `@fastify/rate-limit`, `@fastify/static`,
`@fastify/swagger`, `jose` (JWT + Google JWKS), `drizzle-orm`, `better-sqlite3`, dev

`@tanstack/react-query`, `i18next`, `react-i18next`, `lucide-react` (same majors as the
launcher). Root dev: `concurrently`. Pin versions in the lockfile; no other new runtime deps.

- **D30** US-C5, US-C6, US-D6 confirmed: drop "(proposed, D20)".

**Calls made in planning (no owner decision; reviewers may challenge):**
- The last active admin can't be demoted or suspended, and an admin can't suspend or demote
  themselves (`CONFLICT`, `details.reason: 'lastAdmin' | 'self'`).
- A 5xx, 429, timeout or network error counts as offline (grace applies); a 401 from refresh
  means the device was revoked (session removed).
- The API base URL is fixed per launcher build (`MAIN_VITE_API_URL`, default
  `http://localhost:4000`); unpackaged builds honour `NEXTLEVEL_API_URL`.
- The launcher keeps one secret, `auth.session` (JSON: device id, refresh token, profile, last
  entitlement, local check time), in `secrets.bin`.
- `ADMIN_EMAILS` promotes an account to `admin` **when the account is created** (bootstrap);
  a later demotion in the console sticks.
- The allow-list gates **sign-in** (new and returning users); to stop an existing user, suspend
  them. Changing the allow-list never touches existing sessions.
- Sign-out revokes the device on the server (frees a device slot); the next sign-in creates a
  new device.
- Admins have no device limit and get every scope (data model §5).
- When the OS store is unavailable, sign-in still works for that run (session in memory) and the
  Account app says the sign-in won't be remembered.
- Admin settings PATCH has no revision check (one operator); user PATCH neither. `CONFLICT` is
  used only for the admin guards above.
- `last_seen_at` (users, devices) is updated on refresh and entitlement reads.

## Global Constraints

- **Node 24**, ESM, imports with `.ts` extensions. `apps/api` runs as `node src/server.ts` (no
  build); its `tsconfig.json` sets `"erasableSyntaxOnly": true` (no enums, no parameter
  properties, no namespaces).
- **API env** (Zod, refuse to start with a clear message): `NODE_ENV`, `PORT` (default 4000),
  `PUBLIC_URL`, `DATABASE_URL` (`file:` path), `JWT_SECRET` (≥ 32 bytes base64),
  `JWT_SECRET_PREVIOUS?`, `GOOGLE_CLIENT_ID_DESKTOP` / `GOOGLE_CLIENT_SECRET_DESKTOP` /
  `GOOGLE_CLIENT_ID_WEB` / `GOOGLE_CLIENT_SECRET_WEB` (required unless `AUTH_STUB=1`),
  `ADMIN_EMAILS` (comma list, ≥ 1), `BILLING_ENABLED` (must be `false` in M7), `AUTH_STUB`
  (refused when `NODE_ENV=production`), `ADMIN_DIST?` (built admin folder), `ADMIN_ORIGIN?`
  (dev redirect after admin sign-in). Storage variables stay for M9 (not read yet).
- **Tokens (ADR-006, security §2):** access JWT HS256, 15 min, header `kid` = first 8 hex of
  SHA-256(secret), `iss: 'nextlevel-api'`, `aud: 'nextlevel-launcher'`, claims `sub` (user id),
  `did` (device id), `role`; verification accepts the current and previous secret. Refresh
  token: 32 random bytes base64url, 30 days, stored as SHA-256 hex, rotated on every use;
  presenting a replaced token revokes the device and all its tokens. Device-limit ticket: JWT
  `aud: 'nextlevel-device-limit'`, 5 min.
- **Admin session:** cookie `nl_session` (32 random bytes, stored hashed in `admin_sessions`),
  `HttpOnly`, `SameSite=Strict`, `Path=/`, `Secure` when `PUBLIC_URL` is https, 8 h idle
  timeout; CSRF double-submit: cookie `nl_csrf` (readable) must equal header `X-CSRF-Token` on
  every non-GET cookie-authenticated request (`FORBIDDEN` otherwise).
- **Rate limits:** auth routes 10/min/IP; everything else 300/min/user (IP when anonymous);
  `RATE_LIMITED` + `Retry-After`.
- **Every route declares `config.role`**: `'public' | 'device' | 'admin'` (`device` = launcher
  Bearer). Registration without it throws.
- **Error envelope** `{ error: { code, message, requestId, details? } }`; new shared codes:
  `UNAUTHENTICATED` 401, `FORBIDDEN` 403, `SUBSCRIPTION_REQUIRED` 403, `SUSPENDED` 403,
  `DEVICE_LIMIT` 409, `NOT_ALLOWED` 403, `RATE_LIMITED` 429 (plus existing `VALIDATION_FAILED`,
  `NOT_FOUND`, `CONFLICT`, `INTERNAL`). Never a stack trace in a response.
- **Entitlement:** `checkedAt` = server now; `offlineUntil` = `checkedAt + graceDays`
  (`app_settings.graceDays`, default 14, 1–90). Status order: suspended → `suspended`; admin →
  `active`, all scopes, `plan: null`; else (billing off) `active` on Default.
- **App settings defaults:** `graceDays: 14`, `signUpMode: 'allowList'`, `allowList: []`
  (lowercased emails, ≤ 1000), `banner: null` (≤ 280 chars).
- **Google:** scopes `openid email profile`; authorize `https://accounts.google.com/o/oauth2/v2/auth`
  with `code_challenge_method=S256`; token `https://oauth2.googleapis.com/token`; ID token
  verified with Google's JWKS (`iss` `accounts.google.com` or `https://accounts.google.com`,
  `aud` = the client id used, `exp`, `email_verified === true`). Emails compared lowercased.
- **Stub (`AUTH_STUB=1`):** personas `admin`, `subscriber`, `suspended`, `outsider` →
  `<persona>@nextlevel.test`, Google sub `stub-<persona>`; `admin`, `subscriber`, `suspended`
  count as allow-listed, `suspended` is created suspended; codes are single-use, 60 s, PKCE-checked.
- **Launcher timings:** entitlement check every 60 min while signed in; API request timeout 10 s;
  browser wait 5 min; loopback on `127.0.0.1`, random port, path `/callback`.
- **Secrets never leave main / never logged:** refresh token, access token, ticket, Google code,
  verifier. API logs (pino) carry user id and request id, never emails or tokens.
- **Files:** components ≤ 200 lines, files ≤ 400 (`apps/launcher/src/main/index.ts` is 469 today;
  Task 9 brings it under 400); main tests never import renderer files.
- **i18n:** every visible string in `en.json`/`pt-BR.json` (launcher) or
  `admin.en.json`/`admin.pt-BR.json` (admin) — python script, `ensure_ascii=False`,
  `newline=''`; the loopback page text comes from `main/i18n/mainText.ts`.
- **Fixtures:** `*.test` emails and invented names only; no real Google tokens, client ids or
  secrets in code, tests or logs. No test touches the network (Google is faked with a local
  JWKS and an injected `fetch`).

## Review Focus

1. **Two refreshes at once** (hourly check + an Account app action, or boot + wake): the second
   would present the already-rotated token and trigger reuse detection, revoking the user's own
   device. Main must single-flight refreshes. Pinned in Task 9.
2. **The clock moves while offline** — set forward past the grace, or back before the last check:
   offline access is allowed only while `localCheckedAt − 5 min ≤ now < localCheckedAt + grace`.
   Pinned in Task 9.
3. **Odd loopback traffic** — a request with the wrong `state`, `error=access_denied`, no `code`,
   a second callback after success, `/favicon.ico`: only the first `/callback` with the matching
   state completes; `access_denied` → `cancelled`; everything else 404 and keeps waiting.
   Pinned in Task 8.
4. **API down at sign-in time** (not at boot) — the sign-in screen must show "Can't reach
   NextLevel" with retry within 10 s, never hang on "Waiting for your browser…". Pinned in Task 9.
5. **A demoted or suspended admin with an open console tab** — their next admin request returns
   `FORBIDDEN`/`SUSPENDED` and the console returns to sign-in. Pinned in Task 12.
