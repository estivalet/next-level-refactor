# M1a Desktop Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the M0 Hello screen with the desktop shell: desktop icons, movable and resizable windows, a dock-style taskbar with a clock, and a Start menu with search and Quit. The Settings app opens in a window, showing an About section with the app version. This plan also closes the M0 review's hardening findings.

**Architecture:** Window state lives in a pure reducer (`windowManager.ts`) behind a small React context. That keeps every rule (focus, z-order, single instance, bounds clamping) unit-testable without a DOM. Drag and resize math are pure functions; the hooks only wire pointer events to them. Apps register in one typed registry. IPC state goes through TanStack Query hooks in each feature's `api.ts`, never through `window.nextlevel` directly in components.

**Tech Stack:** Existing M0 stack plus `motion`, `lucide-react` and `@tanstack/react-query`.

**Spec:**
- Screen spec S6 and the IA (`docs/02-design/04-information-architecture.md` §1, navigation rules).
- The FR-SHELL requirements added in Task 1.
- NFR-A11Y-1, NFR-SEC-1.
- `docs/06-legal/security-and-privacy.md` §3.
- `docs/03-architecture/coding-standards.md` (React, Electron).
- The current NextLevelOS shell as a **visual and behavioral reference only**: `src/context/OSContext.tsx`, `src/components/{Desktop,Window,Taskbar,StartMenu}.tsx`. Read it, don't copy it. The owner chose the current NextLevelOS look over the S6 wireframe on 2026-10-21.

## Global Constraints

- **Look (owner decision):**
  - Dark gradient desktop.
  - Floating, centered, dock-style taskbar: Start button, a separator, open-window entries, a separator, tray with the clock.
  - Windows have macOS-style traffic-light buttons on the left (close, minimize, maximize) and a centered title.
  - The Start menu is a dark glass panel with a search box and an app list.
  - Accent colour `#990033` for the Start button.
- Components ≤ 200 lines, files ≤ 400 lines. Feature folders:
  - `apps/launcher/src/renderer/features/shell/`
  - `apps/launcher/src/renderer/features/settings/`
  - `apps/launcher/src/renderer/apps/registry.ts`
- All user-visible strings go through `t()`, with keys in `packages/shared/src/i18n/en.json`. That includes aria-labels.
- **NFR-A11Y-1:**
  - Every control is a real `<button>` or `<input>` with an accessible name.
  - Visible focus ring (`focus-visible:ring-2`).
  - Everything works from the keyboard: Tab reaches desktop icons, taskbar and window buttons; Enter or Space activates; Esc closes the Start menu.
  - Dragging is never the only way to do something: maximize/restore covers placement.
- Animations use `motion` and are disabled when `prefers-reduced-motion` is set (`useReducedMotion`).
- Components never touch `window.nextlevel`; they call feature hooks that go through `getBridge()`.
- Electron hardening per security doc §3. The CSP becomes `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' nextlevel: data:; media-src 'self' nextlevel:; connect-src 'self'`. `'unsafe-inline'` styles are needed for Vite's dev style injection and Motion; `connect-src` gains the API origin in M7.
- Conventional Commits; branch `feat/m1a-shell`. Nothing reads or imports `../NextLevelOS`.

## Review Focus

1. **The desktop area resizes** (window smaller, display change) while windows sit near the right or bottom edge. Each window's title bar must stay reachable, so positions are re-clamped when bounds change. Pinned in Task 3 (`clampToBounds` on `setBounds`).
2. **Closing or minimizing the focused window.** Focus moves to the next-highest visible window, not to nothing, so the keyboard user isn't stranded. Pinned in Task 3.
3. **A renderer navigation attempt.** A link with `href="https://…"`, `window.open`, or a drag-dropped file must not load remote content into the app window. Navigation is denied, and http(s) URLs on the allow-list open in the system browser. Pinned in Task 2 (`isAllowedNavigation`, `externalUrlAllowed`).
4. **The bridge is missing or rejects** (preload failed, IPC rejected). The About section shows "Version unavailable" and the shell still renders. Pinned in Task 7.
5. **Fast double activation** (double-click on a desktop icon plus Enter, or clicking the taskbar while a window opens). Exactly one Settings window opens. Pinned in Task 3 (single-instance `open`).

### Task 3: Window manager reducer

**Files:**
- Create: `apps/launcher/src/renderer/features/shell/windowManager.ts`, `windowManager.test.ts` (same folder)

**Interfaces:**
- Produces:
  - `type Rect = { x: number; y: number; width: number; height: number }`
  - `type Bounds = { width: number; height: number }`
  - `interface ShellWindow { id: string; appId: AppId; rect: Rect; minimized: boolean; maximized: boolean; z: number }`
  - `interface WindowState { windows: ShellWindow[]; focusedId: string | null; nextZ: number; nextSeq: number; bounds: Bounds }`
  - `initialWindowState(bounds: Bounds): WindowState`
  - `type WindowAction = { type: 'open'; appId: AppId; size: { width: number; height: number }; singleInstance: boolean } | { type: 'close' | 'focus' | 'toggleMinimize' | 'toggleMaximize'; id: string } | { type: 'move'; id: string; x: number; y: number } | { type: 'resize'; id: string; width: number; height: number } | { type: 'setBounds'; bounds: Bounds }`
  - `windowReducer(state: WindowState, action: WindowAction): WindowState`
  - Constants: `MIN_WINDOW = { width: 320, height: 200 }`, `TITLE_BAR_HEIGHT = 36`, `CASCADE_STEP = 30`.
  - `AppId` comes from Task 5's registry as `type AppId = 'settings'`. Define it in `windowManager.ts` as `export type AppId = string` here; Task 5 narrows it with no changes to this file's logic.
- Rules the tests pin, all named `FR-SHELL-n: …`:
  - **FR-SHELL-1/3 open:** a new window gets id `` `${appId}-${nextSeq}` ``, z = `nextZ`, and focus. Its position is centred in the bounds, offset by `(count % 5) * CASCADE_STEP`, and the result is clamped. Opening a `singleInstance` app that is already open focuses (and un-minimizes) the existing window and adds none. Opening twice in a row yields one window.
  - **FR-SHELL-2 focus:** raises z to `nextZ` and un-minimizes. Focusing the already-focused, top window keeps the state identical (`toBe` the same object).
  - **FR-SHELL-2 close:** removes the window. If it was focused, focus moves to the highest-z non-minimized remaining window, or `null`.
  - **FR-SHELL-2 toggleMinimize:** minimizing the focused window moves focus as for close; restoring focuses it.
  - **FR-SHELL-2 toggleMaximize:** flips `maximized` and focuses; `rect` is kept, so restoring returns to it.
  - **FR-SHELL-2 move:** clamps so `x ∈ [-(width - 80), bounds.width - 80]` and `y ∈ [0, bounds.height - TITLE_BAR_HEIGHT]`. At least 80 px of title bar stays on screen and the title bar never goes above the top.
  - **FR-SHELL-2 resize:** enforces `MIN_WINDOW`, with width capped at `bounds.width` and height at `bounds.height`.
  - **setBounds:** stores bounds and re-clamps every window's rect (Review Focus 1).
