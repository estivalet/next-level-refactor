# M4 Themes Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The launcher gets a fullscreen front-end: the six NextLevelOS themes run on a
platform-neutral engine in `packages/themes`, read everything through a `ThemeHost`, work with a
gamepad, keyboard or mouse (remappable), read art from theme packs with a shared-folder fallback
and a coverage report, and the launcher can boot straight into a theme.

**Architecture:**
- `packages/shared` gets the front-end contracts: menu tree, theme game rows, art index, pack
  manifest, theme options, input settings, and `nextlevel://` URL builders.
- Main gets a **media index** (`game_media`, filled by the scan), the **`nextlevel://` protocol**
  (game media by id + kind, menu art by root + relative path, HTTP Range), a **FrontendService**
  (generated menu tree + whole-level game rows) and an **ArtIndexService** (file lists of the
  shared art folder and the theme's pack, plus the pack's `theme.json`).
- `packages/themes` gets the engine ported from NextLevelOS `src/themes/engine` (reducer, level
  model, art builders, pack merge, coverage), an **input layer** (physical key/button →
  `InputAction` from settings, with repeat; theme keymap `InputAction` → `NavIntent`), the
  `ThemeHost` interface, `ThemeEngineProvider` and a `FakeThemeHost` for tests. Themes never fetch
  `/data/*.json`, never call the bridge, never probe the disk (ADR-010).
- The renderer implements `LauncherThemeHost` over `window.nextlevel` and hosts the front-end as a
  fullscreen layer over the desktop shell.
- **Four PRs**, each on its own branch, same workflow as M3 (inline TDD → fresh Opus reviewer for
  the branch → fixes with failing-first tests → PR → CI green → owner OK → squash-merge):
  **M4a** headless engine, host, input, media (Tasks 1–11, `feat/m4a-themes-engine`);
  **M4b** front-end mode, Big Box, boot target (Tasks 12–16, `feat/m4b-big-box`);
  **M4c** Big Box List, Console Home, PS5 Style, theme switcher (Tasks 17–20, `feat/m4c-themes`);
  **M4d** HyperSpin Classic, Showcase, theme options and packs/coverage in Settings, release
  v0.4.0 (Tasks 21–25, `feat/m4d-themes-packs`).

**Tech Stack:** Existing stack. `packages/themes` gains peer deps `react`, `react-i18next`,
`motion`, `@tanstack/react-virtual` (already in the launcher). No new runtime libraries.

**Spec:**
- FR-THM-1..6, US-C1 (gamepad), US-C2 (return focused on the same game), NFR-PERF-1/2/4.
- Architecture §3 (dependency rule), §4.4 (ThemeHost); ADR-010; data model §2 (`general.bootTarget`,
  `storage.assetsPath/themesPath`, `themes`, `input`), §2.5 (theme options precedence), §4
  (`game_media`, game and menu art kinds); IA (front-end ↔ shell, back always available, Settings
  → General/Themes/Input); screen spec S5.
- Reference (read-only): NextLevelOS `src/themes/**`, `docs/themes.md`, `electron/mediaRange.cjs`,
  `electron/protocolScheme.cjs` (+ tests) @ 3d530b7. Port with tests; note the source in the commit.

## Global Constraints

- **Boundaries:** `packages/themes` imports only `@nextlevel/shared`, React, `react-i18next`,
  `motion`, `@tanstack/react-virtual`; no Node, Electron, `window.nextlevel` or `fetch('/data/…')`.
  Themes reach data only through `ThemeHost` (FR-THM-6). `packages/*` never import `apps/*`.
- **URLs:** `nextlevel://media/<gameId>/<kind>` and `nextlevel://art/assets/<rel>` ·
  `nextlevel://art/pack/<themeId>/<rel>`; `<rel>` is `/`-separated, each segment
  `encodeURIComponent`-encoded. Main resolves only inside the configured root (no `..`, no
  absolute, no drive letters, `realpath` must stay under the root) → else 404. No `?p=<path>`.
- **Art layout (unchanged from NextLevelOS):** `logo/<variant>/<name>.png`,
  `background/<style>/<name>.{jpg,png}`, `background/wallpaper/<name>.{jpg,png}`,
  `video/<name>.mp4`, `art/hardware/<name>.png`, `pointer/<name|_default>.png`,
  `system-info/<name>.json`, `sound/<move-menu|move-games>.{wav,ogg,mp3}`. `<name>` is the menu
  node `name`. Pack candidates come before every shared candidate; `fallback: false` drops the
  shared folder.
- **Theme options precedence (§2.5):** theme module defaults → pack `theme.json` → `settings.themes.entries[id]`;
  `art` keys shallow-merge; `settings` keys shallow-merge; an invalid value falls back to the
  previous layer with a warning (never a crash).
- **Input defaults (US-C1):** gamepad D-pad and left stick (deadzone 0.5) = up/down/left/right,
  A = select, B = back, Start = menu, Y = favorite, X = search, LB/RB = tabPrev/tabNext,
  LT/RT = pageUp/pageDown, View = help, View+Start = toDesktop, R3 = random, L3 = hide,
  Guide unbound. Keyboard: arrows, Enter = select, Escape/Backspace = back, Home = home,
  Tab = menu, F1 and Slash = help, KeyF = search, KeyX = favorite, KeyH = hide, KeyR = random,
  KeyQ/KeyE = tabPrev/tabNext, PageUp/PageDown, KeyM = toDesktop, KeyT = switchTheme.
  Repeat: directions and pageUp/pageDown repeat after `repeatDelayMs` 400 at `repeatRateHz` 10
  (keyboard too; native `e.repeat` events are ignored). Typing into a focused text input never
  produces actions except Escape/Enter/arrows.
- **`InputAction` set:** data model list plus `hide` and `random`:
  `up down left right select back home menu help search favorite hide random tabPrev tabNext pageUp pageDown toDesktop switchTheme`.
- **Perf:** `frontend.games` for a 10k-game system ≤ `perfBudget(300)` ms (NFR-PERF-2); the art
  index for 20k files ≤ `perfBudget(500)` ms, cached until the paths change or `refresh`.
- **Files:** components ≤ 200 lines, files ≤ 400. Main tests never import renderer files.
- **i18n:** every visible string (themes included) in `en.json` and `pt-BR.json`.
- **Tests** carry FR/US IDs. Theme behavior tests run against `FakeThemeHost` + fixtures.
- **Porting:** commit body says `ported from NextLevelOS <path> @ 3d530b7` for every ported file.

## Review Focus

- **Path escape through the protocol** (`nextlevel://art/assets/..%2F..%2Fwindows/win.ini`,
  `%5C`, a junction inside the art folder pointing out, a `themeId` of `..`) → 404, never a file
  outside the root → Task 4.
- **Huge levels** (MAME with 40k games, a collection of 10k) → one `frontend.games` call within
  budget, reducer/focus stay O(1) per move, no per-game IPC → Tasks 5, 8.
- **Unplugged / second / non-standard gamepad, a button held across a level change, window blur
  while holding** → no stuck repeat, no phantom actions, first standard pad wins → Task 9.
- **Art folders that are missing, unreadable, or set to a drive that isn't mounted** → the theme
  renders with text fallbacks, the index is empty, no error loop → Tasks 6, 10.
- **Library changes while a theme is open** (scan finishes, a flag changed in the Library window,
  a launch ends) → the open level refreshes in place and keeps focus on the same game id → Task 10.
