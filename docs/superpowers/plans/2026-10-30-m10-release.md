# M10 Release 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** NextLevel 1.0 ships: a signed Windows installer (and a zip for copy-anywhere use) that
keeps everything inside the NextLevel folder (D50), updates itself from GitHub Releases, can be
locked into kiosk mode with a PIN, optionally syncs a subscriber's settings, menus, collections and
game state across PCs, and talks to a production API on a VPS with catalog files on Cloudflare R2.
The release checklist passes.

**Architecture:**
- `apps/launcher`: packaging (`electron-builder.yml`, NSIS include `build/installer.nsh`),
  `main/update/` (electron-updater with its cache in `<data>\updates`), `main/kiosk/` (PIN, lock
  state, main-side refusals), `main/sync/` (per-kind documents, merge, apply); renderer Settings →
  About (updates), Kiosk, Sync pages, a PIN pad and the kiosk-aware shell.
- `apps/api`: `sync/` (documents with revisions), `minLauncherVersion` (`UPDATE_REQUIRED`),
  `storage/S3Store.ts` (R2, presigned URLs), orphan sweep, pre-migration snapshot
  (the built console is already served by `routes/adminStatic.ts`); `Dockerfile`, `deploy/`
  (compose, Caddyfile, backup), deploy workflow.
- **Four PRs**, same loop as M9 but cheaper (owner, 2026-10-30): inline TDD with the ledger
  `.superpowers/sdd/2026-10-30-m10-release/progress.md` → lint, typecheck, the touched workspaces'
  tests and only the new/changed e2e spec locally (full e2e is CI's) → **one** fresh Opus reviewer
  per PR → fix Critical/Important failing-first → PR → `gh pr checks <n>` → owner OK →
  squash-merge → main push run:
  **M10-0** M9 minors (triaged) + this plan (Tasks 0–3, `fix/m9-minors`);
  **M10a** installer, signing, auto-update, minimum version (Tasks 4–7, `feat/m10a-installer-update`);
  **M10b** kiosk mode + settings sync (Tasks 8–11, `feat/m10b-kiosk-sync`);
  **M10c** production: R2, Docker, deploy, backups, 1.0 docs (Tasks 12–14, `feat/m10c-production`).

**Tech Stack:** new dependencies: `electron-builder` (launcher dev), `electron-updater` (launcher),
`@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner` (API).
CI downloads a pinned `minio.exe` for the S3 contract tests.

**Spec:** FR-SET-5 (sync), FR-SET-6 + US-D4 (kiosk), NFR-UPD-1 (auto-update), NFR-SEC-1; roadmap
M10 row (keeps D50); deployment-and-operations §1–7; architecture §8; api-spec Sync (M10); data
model `settings.kiosk`, `settings.sync`, `sync_documents`; IA Settings → Kiosk, Sync, About;
release-checklist.md (all of it); environment-setup (env vars).

## Owner decisions (D51–D59)

**Asked in one batch on 2026-10-30. Owner: "fine", plus a no-spending rule** ("right now I don't
have plans to spend a penny on this project"). So the recommended options stand, with these
changes:

- **D52 → unsigned for now.** No certificate is bought. The release workflow signs only when
  signing secrets exist; without them it builds unsigned (pre-release or release), and the release
  notes say Windows SmartScreen will warn ("More info → Run anyway"). Signing can be switched on
  later by adding the secrets.
- **D56 → code only, no deployment.** The Dockerfile, compose, Caddyfile, deploy workflow, backups
  and the provisioning runbook are written and tested, but nothing is rented or deployed. The API
  keeps running locally (as today); the deploy workflow runs only on `workflow_dispatch` or an
  `api-v*` tag, which is not pushed in M10.
- **D57 / D40 → R2 prepared, local storage in use.** `S3Store` is written and tested against MinIO
  (any S3-compatible store works, including R2's free tier later). `FILE_STORE=local` stays the
  default. The owner may later keep catalog files on free services (Google Drive, archive.org) or
  locally; `FileStore.downloadUrl` (Task 12) is the seam a future public-URL store would use.
  Nothing for those services is built in M10 (YAGNI).
- **D59 → 1.0 without the paid items.** The checklist lines for a code-signed installer,
  SmartScreen and the production/staging backend are skipped with a written reason
  ("no-spending rule, 2026-10-30"). The beta → 48 h → `v1.0.0` path and the D26/D32 owner checks
  stay.

- **D51 Distribution.** *Recommended:* NSIS "assisted" installer, per-user (no admin prompt),
  folder picker defaulting to `C:\NextLevel` (Program Files refused: not writable, D50); creates a
  Start-menu and desktop shortcut and the Apps & features entry — the only things outside the
  folder, made by the installer and removed by its uninstaller. Updating and uninstalling never
  delete `data\` or `Catalog\`. The same build also ships as a `.zip` (unzip anywhere; manual
  updates). Not electron-builder's `portable` target: it unpacks the whole app into `%TEMP%` at
  every start; `PORTABLE_EXECUTABLE_DIR` is still honoured in case it is ever used.
  *Alternatives:* zip only with our own updater; `portable` target.
- **D52 Code signing.** *Recommended:* Azure Trusted Signing (~US$10/month, signs in CI; check
  you are eligible as an individual in your country). *Alternatives:* an OV certificate on a cloud
  HSM (~US$200–400/year); 1.0 unsigned (SmartScreen warns). Builds without signing secrets are
  unsigned and can only be pre-releases.
- **D53 Updates.** *Recommended:* electron-updater from GitHub Releases; **stable** channel, opt-in
  **beta** (pre-releases) in Settings → About; check at start and every 6 h, download in the
  background, install when NextLevel quits, **Restart to update** in the tray and About;
  "Check for updates automatically" (on). Zip copies get a notice with the download link. The
  API's `minLauncherVersion` shows an "Update required" screen to older launchers.
  *Alternative:* notify only, no background download.
- **D54 Kiosk.** *Recommended:* PIN of 4–8 digits (stored as a scrypt hash). Hides desktop,
  Settings, theme switcher, Catalog, Account and Quit (all ticked by default, each can be
  unticked). Unlock: hold Start (gamepad) or Esc (keyboard) 3 s → PIN pad; unlocked until restart
  or **Lock now**. 5 wrong PINs → 1 minute wait. Forgot the PIN: create an empty file
  `reset-kiosk` next to `NextLevel.exe` and restart (kiosk turns off, the file is deleted).
  *Alternative:* forgot PIN via signing in with Google again (more work).
- **D55 Sync.** *Recommended:* opt-in per PC (off by default), signed-in subscribers only.
  Syncs: language, theme choices and options, sounds, input mapping, scraper preferences, menus,
  collections, favorites, hidden, ratings, play count, play time and last played. Never: paths,
  storage locations, emulators, profiles, per-system folder settings, secrets, kiosk. When: at
  start, 10 s after a change, hourly, and **Sync now**. Conflicts merge per entry (newest wins);
  play counts and time add up across PCs. Games match by system + path inside their storage
  location (catalog games by item); state for a game this PC doesn't have waits until it appears.
  **Delete synced data** in Settings → Sync. *Alternative:* whole-section newest-wins (simpler,
  can lose a change made on another PC).
- **D56 Hosting.** *Recommended:* one Hetzner VPS (CX22, ~€4/month) with Docker Compose and Caddy
  (Let's Encrypt TLS), Cloudflare DNS, Cloudflare R2 for catalog files and backups (separate
  keys), images on GHCR, deploy on tag `api-v*`. You provide the domain and accounts; I write the
  Dockerfile, compose, workflow and a step-by-step provisioning runbook that you run.
  *Alternative:* a managed host (Fly.io / Render).
- **D57 Downloads from R2.** *Recommended:* the API hands out presigned R2 URLs (files 10 min, art
  1 h); the launcher asks for fresh URLs when one expires mid-download. Uploads still go through
  the API (D41, SHA-256). *Alternative:* stream every download through the API (VPS bandwidth).
- **D58 Billing at 1.0.** *Recommended:* 1.0 supports Stripe live mode (keys by environment), but
  production starts with `BILLING_ENABLED=false` and the allow-list; live billing is switched on
  later by a checklist step that needs D32 first. *Alternative:* live billing on day one (D32
  blocks 1.0).
- **D59 Release gating.** *Recommended:* M10c publishes `v1.0.0-beta.1`; after ≥ 48 h on beta and
  the full checklist (incl. your D26/D32 checks and a signed build) it is promoted to `v1.0.0`.
  v0.8.0 is never tagged on its own: its notes fold into 1.0 and the M8 ledger closes then.
  *Alternative:* keep waiting to tag v0.8.0 first.

**Calls made in planning (no owner decision; reviewers may challenge):**
- Version: every workspace `package.json` gets the release version (`0.10.0` during M10,
  `1.0.0-beta.1` / `1.0.0` at release) through `npm version <v> --workspaces --include-workspace-root
  --no-git-tag-version`; the launcher's `app.getVersion()` and the API health version read them.
- Settings `schemaVersion: 3` adds `updates: { channel: 'stable'|'beta'; auto: boolean }`
  (`stable`, `true`), `kiosk: { enabled: false; pinHash: null; hide: [...all] }` and
  `sync: { enabled: false; deviceKey: string }` (`deviceKey` = uuidv7 created by the migration;
  names this PC's play counters). Migration with backup first, as v1 → v2.
- The launcher sends `X-NextLevel-Version` on every API call. `app_settings.minLauncherVersion`
  (semver or null, console Settings) → device routes answer `426 UPDATE_REQUIRED` to older
  versions; `/v1/health` and auth start are exempt.
- No crash reporting (Sentry) in 1.0. Privacy policy and terms: plain-language drafts in
  `docs/06-legal/` for the owner to review (needed for Google's OAuth verification and Stripe
  live); not legal advice.

## Global Constraints

- D50: nothing the launcher (or its updater) writes lands outside the NextLevel folder; the
  installer's shortcuts and Apps & features entry are the only exceptions (D51).
- Updating or uninstalling never deletes `<install>\data\` or `<install>\Catalog\`.
- Node 24 type stripping in `apps/api` (erasable syntax only); every API route has `config.role`;
  errors through `apiError(code)`; response schemas without transforms.
- Renderer never talks to the API or the file system; new IPC channels are Zod contracts in
  `packages/shared/src/ipc/` with validated input.
- New user-facing text in `en` and `pt-BR`.
- Every admin mutation is audited (C11): `settings.update` covers `minLauncherVersion`.
- No backslashes through Bash heredocs; files with Write/Edit.

## Review Focus

1. **Upgrade over a used folder:** installing 1.0 over a folder with `data\` and `Catalog\` (and
   running the uninstaller) keeps both, byte for byte — packaging smoke test in Task 7.
2. **Updater writing outside the folder:** the download cache, `pending\` installer and logs stay
   in `<data>\updates` / `<data>\logs` — Task 5 asserts the adapter's paths; Task 7's smoke checks
   `%LOCALAPPDATA%\nextlevel-updater` doesn't appear.
3. **Kiosk bypass through IPC:** with kiosk locked, `settings.save`, `app.quit`, catalog
   install/uninstall and opening the desktop are refused in main (`KIOSK_LOCKED`), not just
   hidden — Task 8 tests each channel.
4. **Sync bringing another PC's paths or deleting local data:** a pulled settings document with
   path keys is ignored; a game missing here keeps its synced state without touching the library;
   a skewed clock can't make an old change win forever (server stamps `updatedAt`) — Task 11.
5. **A presigned URL expiring mid-download** (4 GiB file, 403 from R2 after 10 min): the launcher
   re-issues URLs and resumes from the partial file — Task 12 test in DownloadService.
